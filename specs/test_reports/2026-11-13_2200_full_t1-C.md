**Block 19 -- the sampler**

- O19.1 (import boundary): `ev_config` and `ev_plan` import only the
  standard library and the pipeline's own modules (they run on the login
  node's python); the sequencer (`hpc/pipeline/*.py`, `stages/`) imports
  no evaluation module.
- O19.2 (ensembles): `<runs_root>/<q>/<tag>_best` for every search, and
  `<tag>_best_alt` once it has BEST_FIT_COMPLETE.json. Name `<q>:<arm>`,
  stem `<q>_<arm>`. The arm is the members' records' `arm`, a refusal if
  they disagree. Cohorts: every `synthetic.real` entry for S-A1, else
  [q.real].
- O19.3 (theta-dagger, D_R3+; analytic): per donor, theta_dag_k = theta*_k
  on the axes that are not free and theta*_k + delta on the free axes. On
  axis 7, when it is free, the value is min(theta*_7 + delta, (1 - L_7) /
  (U_7 - L_7)) = 1. delta = `free_axis_range_shift(GapSpec(**gap_spec))` =
  0.35 pi (0.105 at pi = 0.3), and `in_box` = all(0 < theta_dag < 1),
  strict at both ends. Identity: the unshifted affine map at theta_dag
  equals the shifted map at theta*, the duty's clip included, to float64
  roundoff. R0 (pi = 0), or a gap without `range_shift`, has no `<r>dag`
  data set.
- O19.4 (log-density outside the box): `logq_ref_members[i, m]` = -inf
  wherever `in_box[i]` is false, whatever the flow returns there.
- O19.5 (mixture, E1): `logq_ref[i]` = logsumexp_m(logq_ref_members[i, m])
  - log M, and the mixture at a draw is >= that draw's own member's density
  / M. Both can be recomputed in float64 from the members' densities.
- O19.6 (draws): n_post / M draws per member, in member order
  (`draw_member` = repeat(arange(M), n_post/M)); the same seed gives
  identical files; member k's draws on D are seeded by `seed_of(seed, D) +
  k`, the same for every ensemble (common random numbers).
- O19.7 (rebuild oracle): on D_sim each member's -log q at theta_ref equals
  its `_perrow.npz` `nll` row for row, and on its own cohort its
  `nll_pseudo_real`, within `oracle_tol` (synth 2e-3 nats; must lie in
  (0, 0.1]). Otherwise: exit 3 naming the member, the largest and the mean
  difference and the tolerance, with nothing written (E19d). A split hash
  that differs from the record's is refused.
- O19.8 (rows): D_sim is the report rows of the members' split, in global
  row order; `calib` is the first row of each donor; `ppc_rows` are the
  first `ppc_rows` calibration rows (D_sim) or every window (a cohort).
  Cohort rows are every window in bank order, theta_ref the bank's theta.
- O19.9 (npz contract): the keys, shapes and dtypes listed in the entry,
  with `ppc_draw_idx` = j n_post / ppc_draws.
- O19.10: every draw lies in the open unit box.
- O19.11 (CLI): exit 0 with `EVAL SAMPLE OK: <stem>`, 2 on the arguments,
  3 on a refusal. The calibration bank is checked before any sampling: the
  box prior, a builder seed no bank of the project has, `cal_n` windows of

**Block 20 -- the quantities**

- O20.1: the HPD rank gamma_i = (1/n_post) #{s : logq_draws[i,s] >
  logq_ref[i]} (strict >), and C(beta) = (1/n) #{i : gamma_i <= beta} (<=)
  on beta = 0, 0.01, ..., 1 (101 points). Oracle: hand-computed values.
- O20.2 (calibration under the exact posterior): conjugate Gaussian on 10
  axes, theta ~ N(0, I), x = theta + N(0, 0.25 I), posterior N(x/1.25,
  0.2 I). C(beta) lies within the KS bound of the diagonal; a posterior
  half as wide gives a signed area < -0.1, twice as wide > 0.1.
- O20.3: the binomial band's half-width is 1.96 sqrt(0.25 / n). The
  cohort's band comes from `bootstrap_n` donor resamples and does not
  change when each donor's rows are copied.
- O20.4: l_i = -logq_ref; its mean over the in-box rows; the donor means;
  each member's mean.
- O20.5 (recovery): draws N(mu_i, 0.1^2) with theta_ref = mu_i give
  contraction 0.88, 90 % coverage 1 and z 0; shifted by 2 SD, coverage 0
  and z -2.
- O20.6 (paired, E3): d_i = l_i(E_{q,A(q)}) - l_i(E_{q,A1}) on the rows
  in box for both, with a donor-cluster bootstrap. sigma_seed = the larger
  over the two arms of the SD over members of the members' mean NLL. The
  verdict is (|Dbar| > 2 sigma_seed) and (the interval excludes 0).
- O20.7 (search): the trials in proposal order (`pipeline_rounds.json`),
  the running minimum of `nll` per arm over the ok trials, the search's
  finalist.
- O20.8: NaN and inf are written as JSON null. An ensemble that is not
  sampled, or was sampled with other SAMPLE_PARAMS, is left out and named;
  with none current: exit 3. One worker and three give the same files.
- O20.9: SBC with a Holm family over the 10 axes rejects a shifted axis
  alone. TARP with references read out from x sees a posterior equal to
  the prior; with uniform references it does not. MMD p > 0.01 when both
  sets come from one law, <= 0.01 for two laws. Theta-dagger's out-of-box
  rows are out of the NLL and in SBC.

## Problems in the spec

- S301: block 18's test oracles ("the committed v3 loads", "the committed
  file's 17 stages", "Dry run: the four alternative best fits'
  `ba_synth_s<k>` lines") and sec. 6's row ("17 stages with v3") describe
  synth.json v3. So does block 22's E22a ("nine folders not complete"; the
  smoke test now checks 5). Block 26 made v4: 13 stages, every
  `alt_best_fit` false, T18 on a v3-like copy. The entries were not
  amended.
- S302: block 19's API `ev_data.pseudo_true(theta, gap_spec)` and sec.
  2.5's D_R3+ (theta^dag_7 = min(theta*_7 + delta, 1); K_F = {7, 8, 9};
  Q-E3's expected 1 - 0.895^3 = 0.28 outside the box) were written for the
  default split. Block 25 (v4: label axes 0-7, free axes 8-9) changed the
  function to `pseudo_true(theta, gap_spec, free_idx)` and leaves the duty
  unshifted in synth. Sec. 2.4, 2.5 and the Notation still give K_L =
  {0..6}, K_F = {7, 8, 9} with no v4 qualification. Tested here in block
  25's form.
- S303: sec. 2.5 defines sigma_seed on the members' L_pseudo_real (a
  cohort quantity); block 20 defines it on "the members' mean NLL on D" for
  every data set, D_sim included. Neither states the SD's ddof: the code
  uses 1, and with M = 5 the two conventions differ by a factor of 1.118
  in 2 sigma_seed. The marginal SD sigma_{i,k} leaves ddof open too (the
  code: 1).
- S304: `seed_of(seed, D)` is a contract (common random numbers across
  ensembles; block 23's examples) but is never defined in SPEC.md; the
  base of k in `seed_of(seed, D) + k` is not stated either.
- S305: the eight fixed statistics are named but not defined (SD ddof,
  quantile method, the burst-fraction threshold, the roughness), so an
  independent oracle can check only the mean and the max exactly (done)
  and bound the SD and q90.
- S306: block 20 asks for "a binomial 95 % band" and E20a for "the
  binomial band's half-width 1.96 sqrt(0.25 / n)". The code uses exact
  binomial quantiles at each beta (zero width at beta 0 and 1). The two
  agree only at beta = 1/2.
- S307: block 22 does not say whether the report's "after the sampling
  jobs" holds when `--what` leaves `sample` out (F304).
- S308: block 18 does not say what `best_fit_alt_<q>` does when the other
  arm has no completed trial. Today the tuner exits non-zero, the stage
  refuses (`STOP: stage ... refused`) and, by sec. 2.2's rule 4, the
  whole run stops.
- S309: the PPC and L-C2ST draw indices when n_post is not divisible
  (F308).
- S310: sec. 7 records pytorch-metric-learning 1.6.3 in the sandbox,
  against `>=2.3` in `hpc/requirements.txt`; neither bounds it above,
  although 3.0 breaks the DSN loss (F306).
- S311: block 19 says the ensembles are `<tag>_best` and "once it has its
  BEST_FIT_COMPLETE.json, `<tag>_best_alt`". The code considers an alt
  folder only when the search's `alt_best_fit` is true in the
  configuration: a complete alt folder of an earlier configuration is
  ignored, and an incomplete one is listed as not complete.
- S312: block 23's "per cohort with contaminated windows, as many
  contaminated windows drawn the same way": as many as
  `examples_per_condition` (the code) or as the cohort's example count?
