## Problems in the spec

- S1 Amendment 5 (sec. 3.1, `searches`) lists "the label axes" among the name
  rules:
  - `synthetic.builder.label_axes` are integers with no string rule;
  - the string rule the code changed besides the four named ones, the axis
    names of `search.space_overrides`, is not in the list.
- S2 Amendment 5 holds the name rules to the whole string, but not the formats
  of the same table (`hh:mm:ss`, PBS memory) or the plain strings (F1).
- S3 Block 7's reset tool promises that "a file ... that changed makes the
  CODE stale". The digest holds names, entry counts and byte counts, and
  amendment 5 says "with its size". A request replaced by another of the same
  size between the listing and `--confirm` keeps the CODE valid: checked, 124
  bytes and CODE f5c1c808 both times.
- S4 Amendment 4's "a plan that cannot be read" leaves open whether every task
  is read. The code reads up to the first task with simulations:
  `[5, "x", {}]` gives TEST_INDEX 0 with no refusal, while `["x", 5]` is
  refused.
