## Problems in the spec

- S1. Block 35's build note ("the oracle runs on every row of D_sim, so a row
  outside the open box refuses, as in block 19") contradicts sec. 2.6. Sec.
  2.6 defines the NLL over the rows whose theta is in the open box, and
  block 36 writes `n_out_of_box`. Block 19's synthetic banks keep theta in
  the open box (block 11's amendment), but the extractor's banks do not
  guarantee it (F1).
- S2. (R10)'s "SD close to sqrt(alpha_gate (1 - alpha_gate) / (N_null + 2))"
  is 11 % high at N_null = 50: the exact SD of Beta(2, 49) is 0.0269, against
  0.0302, because k_gate / (N_null + 1) = 0.039 there and not alpha. It is
  within 1 % at 500 and 1,000. The quoted bands are exact.
- S3. Block 33's build note "a number of the configuration is accepted as an
  int or a float" is ambiguous for the integer keys. The code refuses
  `n_post` 1000.0 (`_int_at_least` requires an int). The tests read the note
  as covering only the non-integer keys.
- Block 34 states that `bandwidth_grid` "subsamples only above 1,000 points,
  so never at the cap of 800", but the configuration admits any n_ref (F4).
