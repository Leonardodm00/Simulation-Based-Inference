## Problems in the spec

- S1 (F1). Sec. 2.5 defines Dbar(E, E') as the mean over the donors of
  Delta_d. Blocks 20 and 27 prescribe `paired_bootstrap(d, groups=donor,
  within="all")`, whose estimate is the mean over rows. The phrase "one copy
  of each donor enters the bootstrap" is true of `within="all"` only when
  every donor has the same number of rows. E27b's "Dbar ... recomputed from
  the two samples" does not say which mean, and the smoke test recomputes the
  row mean.
- S2. sigma_seed: the SD's degrees of freedom and its rows are not stated
  (block 20: "the SD over members of the members' mean NLL on D"; E27b: "the
  ok rows"). The code takes ddof 1 over each ensemble's own in-box rows with a
  finite density. The tests here assume the same; the two readings coincide
  on this project's data.
- S3. Text superseded without a bracket: block 22's E22a still expects
  "nine folders not complete" for the committed `synth.json` (v4 gives five,
  and the smoke test checks five); block 20's Public API still names
  `paired_<q>_<D>.json` "per search with a term"; block 21's file list
  still names `searches/<q>/` with `arms_coverage`, `arms_nll_<D>`,
  `arms_ppc_<D>`, `arms_lc2st_<D>` and `arms_forest_<D>`.
- S4. Block 27: "A project of v3's design ...: its comparisons are block

  rule (b), the committed v3 (S-A2 and S-A5 searches on R0 and on R3) also

- S5. Block 28's captions must end "with a full stop". `make_all`'s returned
  captions do not, while FIGURES.md appends one; which text is the caption

- S6. Unspecified behaviour: a paired data set with fewer than two donors
  (F4); an unreadable sample provenance (F5); the files of an earlier report
  in `metrics/` and `figures/` (F7); a one-member ensemble's sigma_seed (F6).
