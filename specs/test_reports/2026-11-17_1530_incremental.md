## Problems in the spec

- S1 Sec. 3.1, `searches`: the list is not said to be non-empty, as
  `synthetic.searches` is; the code refuses `[]`.
- S2 Block 7 (j)'s K_cfg does not hold `replicate.*`.
  - A change of the pair rule accepted while a search with the replicate
    term runs continues the search: the GP ledger mixes trials trained under
    two rules, and the best fit's members may train under another rule than
    their trial.
  - Checked on a copy of linddup.json: after `replicate.pairs` changes,
    `identity_refusal(A5's identity, the new view)` is None. Only the
    configuration's digest changes, so a submission with
    `--accept-config-change` continues the search.
- S3 Block 30 names `searches` list or null only. For a synthetic
  configuration the command requires `--search` among `synthetic.searches`'
  names, which the spec does not state.
- S4 The request file's lifetime after the search ends is unstated. It stays;
  `--cancel` is refused after the end; the reset tool does not list or move
  it (F1).
- S5 Block 30: "the command refuses such a request, so only a hand-made file
  gets there" is false after a reset (F1).
- S6 Block 29 specifies the stop line in `status` and the dry run for a
  configuration with a searches list only.
  - For a null configuration, where `stop-search` is allowed, neither shows
    a standing request (checked on a Giulia copy); the search report does.
- S7 Block 32: `<s> simulations` is ambiguous (the accepted deviation: the
  partial topologies' iter_*.npz).
- S8 Block 31: the singleton report line for cross_well with a KEY other than
  donor is not specified.
- S9 Stale Status lines (F2, F3):
  - block 30's regression note "identity ... 1 TODO (block 29's, then)";
  - blocks 7 and 26's "stage 4's joint-space test 9/9 and joint-tune test
